------------------------------------------------------------
第 1 步：双击 SelfTest_Win7.exe
------------------------------------------------------------
它只做两件事：弹一个框、写一个 txt，绝对不碰设备。
正常应该看到标题为「EXE 自检成功」的框，
同文件夹里会多出 SelfTest_result.txt（写着系统版本和 32/64 位）。

  ✔ 弹框了
      → 说明 exe 能在这台电脑跑，继续第 2 步。

  ✘ 还是空白黑窗口 / 没反应 / 弹出别的错误
      → 拍下整个屏幕（连任务栏、任何提示一起拍）
      → 按 Win+R，输入 winver 回车，拍一张系统版本窗口
      → 把照片发我，这种情况要换完全不同的做法

  如果杀毒软件或厂里管控软件弹了拦截提示，也拍下来。

------------------------------------------------------------
第 2 步：双击 OneKeyUnload_Win7.exe
------------------------------------------------------------
正常应该出现一个白色小面板，顶部写着
「一键退出基板 · 辅助工具 v3」，
有大按钮、4 个等待时间输入框、F9 / F12 等快捷键提示。

  ✔ 面板出来了
      → 故障解决。接下来照《现场取点操作卡》做：
        F12 取 4 个点 → 调等待时间 → 勾空跑 → 空片验证 10 次。
        没取过点之前，F9 真实执行是锁住的，这是故意的。

  ✘ 还是空白窗口 / 没有面板
      → ① 拍「整个桌面」，别只拍一个窗口
           （面板可能被别的窗口挡在后面）
      → ② 看同文件夹有没有 OneKeyUnload_log_年月.txt，有就带回来
      → ③ 改试 OneKeyUnload_Win7_alt.exe，结果也拍给我

------------------------------------------------------------
技术说明（给 IT 看，你可以跳过）
------------------------------------------------------------
· 编出来的 exe 全是标准 Win32 GUI 程序（PE Subsystem = 2），
  只调用 kernel32 / user32 / gdi32 等 Windows 自带 DLL，
  导入表里没有 Win8 以上才有的 API，
  也不需要 VC++ 运行库、.NET Framework 或 UCRT。
  所以「Win7 缺构架 / 缺运行库」这条基本可以排除。
· 32 位 Win7 跑不了 64 位 exe，但那种情况会直接弹
  「不是有效的 Win32 应用程序」，不会是一个空白窗口。
· 截图里那个窗口：标题是 exe 完整路径、右侧有滚动条、
  里面一片深色空白 —— 是控制台 / DOS 宿主窗口，
  不是本工具自己画的面板（本工具面板是白底带按钮）。
  常见成因是文件在传输中被截断、被安全软件替换，
  或旧系统加载新版 PE 时进了兼容路径。
· 因此 Win7 版改用较老的 AutoHotkey 运行库重新编译：
    正式版  1.1.30.03 Unicode 32 位  ← 兼容 Win7 / XP 最稳
    备用版  1.1.33.10 Unicode 32 位
  都是 32 位，32 / 64 位 Win7 都能跑。
  原 OneKeyUnload.exe 用的是 1.1.37.02（2023 年版）。
· 同时把 GUI 字体从 Win7 没有的 Microsoft YaHei UI
  改成 Win7 自带的微软雅黑 Microsoft YaHei，少一个变量。
· 本机（Win10）已逐个启动验证 5 个 exe：
  都能打开、中文窗口标题和日志正常、自检框正常弹出。
  但本机没有设备，也模拟不了 Win7，仍需现场确认。
