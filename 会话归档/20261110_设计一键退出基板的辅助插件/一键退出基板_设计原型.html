每步等几秒 · 现场拖动即可

含义是「点完这一步之后，等多久再点下一步」。第 ④ 步的等待只影响工具报告完成的时机，设备动作在点下 Toggle 时已经发生。

一键预设

全局倍率 · 调试时先把整套流程放慢

或自定义 实际等待 = 每步秒数 × 倍率
4.2 秒 · 整套流程预计耗时
1.0 × 全局倍率
③ 最长的一步

现场怎么试出合适的值

第 1 轮：选「保守」预设 + 倍率 2.0，先勾空跑看一遍日志，确认 4 步顺序和窗口名都对。
第 2 轮：维护模式 / 空片 / 无产品，连跑 10 次，看有没有漏步、设备动作是否跟得上。
第 3 轮：把每步逐步缩短，直到找到「刚好不漏步」的值，再往上留 20~30% 余量当正式值。
特别留意 ③ Standby 之后：平台回位、真空释放可能需要几秒，这段别压得太狠。PPT 第 3→4 页计时相差约 7 秒，可作为保守上限参考，但 PPT 没写明这是等待要求。
等待时间只影响「下一步什么时候点」，不会让设备动作变快。调太短的风险是上一步还没完成就点了下一步。宁可先慢，稳了再快。

一句话：取点 = 告诉工具按钮在窗口里的位置。做法是鼠标停在按钮正中间 → 按一下键盘，全程不点击设备按钮，不会给设备发任何动作。

    

      
推荐做法 · F12 四步引导向导（EXE 版 / AutoHotkey 版通用）

      
先把设备软件打开、窗口放到平时作业的位置，然后双击 OneKeyUnload.exe（老 32 位电脑用 OneKeyUnload_x86.exe），面板出现在屏幕左上角。exe 不用装 AutoHotkey。

      
准备　按 F12 启动向导，屏幕左下角会出现一句提示，告诉你这一步该把鼠标停在哪。之后每停稳一个点，再按一次 F12 记录，4 个点共按 5 次。

      
第 1 点　鼠标停在起始页右侧工具栏第 3 个 SETUP（扳手锤子）图标正中间 → 按 F12。听到「嘀」一声、提示跳到 2/4，就记好了。

      
第 2 点　自己用鼠标点一下 SETUP 图标切到 Setup 树页（只换页面，不动设备）→ 鼠标停在 Right Bond Stage 那行文字中间 → 按 F12。

      
第 3 点　自己点一下 Right Bond Stage 打开子窗口 → 鼠标停在右下部 Standby 按钮中间 → 按 F12。

      
第 4 点　同一个子窗口，Status 区第 1 行 Vacuum 的 Toggle 按钮中间 → 按 F12。弹出「取点完成」，结束。

      
按键安全：记录点只用 F12，不用空格 / 回车——那两个键会激活界面上当前有焦点的按钮，可能真的点动设备。取点过程工具不发送任何鼠标点击，但你手动翻页面的那两下例外。若设备软件把 F12 绑定了别的功能，告诉我改成 F7 之类的空闲键即可。

为什么要手动点两下？因为第 2 点的树项在 Setup 页里、第 3 点的按钮在子窗口里，不先把界面切过去就找不到它们。这两下只是翻页面，不触发设备动作；如果贵厂 SOP 认为连翻页面也不该自动做，那就手动翻，不影响取点。

常见问题

        

          
窗口被拖动过了，要重取吗？不用。记的是相对窗口左上角的坐标，窗口整体移动照样准。子窗口每次弹出位置不同，正是用相对坐标解决的。

          
什么时候必须重取？换分辨率、改 Windows 显示缩放（125%/150%）、换显示器、软件升级后界面布局变了、按钮位置挪了。重按一次 F12 即可。

          
为什么用 F12，不用空格 / 回车？空格和回车会激活界面上当前获得焦点的按钮，可能真的点动设备；F12 不会。工具只读取鼠标位置和窗口信息，不发送鼠标点击。

          
鼠标停在工具自己窗口上怎么办？工具会识别出「鼠标停错地方了」并拒绝记录，不会写进错坐标。把鼠标移回设备软件即可。

          
取错了一个点？不用修，重新按 F12 从头走一遍，4 个点整体覆盖。

          
窗口标题是空的 / 没拍到？没关系。向导同时记录窗口类名，标题定位失败时自动用类名兜底；F8 可随时查看。

          
会不会弹确认框？你已确认这 4 步不弹框，所以工具不等也不点任何设备弹窗。工具自己执行前的那一次确认是我们加的安全确认，不是设备弹窗。
